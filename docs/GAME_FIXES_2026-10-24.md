# 두 게임의 우선순위 수정·배포 기록

작업일: **2026-10-24** · 기준: [스킬 기준 점검](GAME_REVIEW_2026-10-24.md)

상태: **P1·P2 6건 수정·검증·공개 배포 완료**

## 수정한 범위

점검 문서의 P1·P2 **6건**을 수정했다. P3의 키 설정, 동료 행동 표시, 성능 최적화는 후속 개선 목록으로 남긴다.

| 항목 | 게임 | 반영한 처리 |
| --- | --- | --- |
| H-01 | 용사월드 | 계정 저장은 복구 기록 쓰기를 확정 시점으로 삼는다. 확정 후 기본 캐시 쓰기가 실패해도 화면을 거래 전으로 되돌리지 않는다. 읽기도 확정된 복구 기록을 우선한다. 이미 클라우드 오류가 있는 상태의 새 저장은 기록을 바꾸기 전에 거절한다. |
| H-02 | 용사월드 | 기기 저장 전용 경로에서 이전 정상본 1개를 보관한다. 읽기 실패 화면에 원본 다운로드·정상본 선택 복구를 추가했다. 현재 기기 저장을 먼저 확정한 뒤 백업을 시도해 백업이 필요한 공간을 먼저 차지하지 않게 했다. 복구 전 손상 원본을 별도로 보존하며, 원본 보존에 실패하면 복구를 중단한다. 기존 단일 쓰기 잠금을 존중한다. |
| T-01 | 탁구왕 | 공통 저장 검증기를 인증·이관·저장에 연결했다. 손상·지원하지 않는 버전은 자동 저장과 게임 시작을 막고 원본 다운로드를 제공한다. 정상 클라우드 기록이 있으면 사용자가 선택해 복구할 수 있다. 정상 1·2버전 이관은 유지한다. |
| T-02 | 탁구왕 | 창 포커스 상실·탭 숨김·업데이트 창 열기 시 정지한다. 키·터치·예약 스윙을 해제하고 직접 재개하게 했다. 대화상자가 열려 있으면 경기 키를 처리하지 않는다. |
| T-03 | 탁구왕 | 응답을 받지 못한 저장의 자료와 기대 수정 버전을 재시도 중 유지한다. 충돌 응답에서는 원격 자료를 다시 읽어 같은 저장의 성공 여부를 확인한다. 그동안 쌓인 새 진행도는 성공 확인 후 새 수정 버전으로 보낸다. 실제 다른 기록은 기존 선택 절차로 처리한다. |
| T-04 | 탁구왕 | 시스템의 움직임 줄이기에서 타격 카메라 흔들림·순간 시야각 변화·화면 섬광을 끈다. 충돌·득점·타격 정지 시간은 바꾸지 않는다. |

서버 테이블·함수·권한을 변경하지 않았다. T-03은 기존 RPC와 읽기 경로를 이용하는 클라이언트 수정이다. Supabase의 호출 형식은 [공식 RPC 문서](https://supabase.com/docs/reference/javascript/rpc)로 확인했다.

## 검증 결과

### 용사월드

- 저장 회귀 검증: **7건 통과**. 복구 기록 확정 후 캐시 실패, 기록 확정 전 실패, 기존 클라우드 오류, 전송 중 새 진행도, 정상본 복구, 저장 공간 부족을 다뤘다.
- 기존 저장 관련 검증 묶음: **28건 모두 통과**. 처음 실행에서 기존 전직 자료 2건이 5직업 고정 수와 치유사 해금·회복 조건을 반영하지 못해 실패했다. 현재 게임 규칙에 맞게 시험 자료를 수정한 뒤 통과했다. 실제 전직 규칙은 변경하지 않았다.
- 최초 수정 버전: **0.9.29**, 저장 공간 보완 버전: **0.9.31**, 날짜 2026-10-24. 한국어·영어·일본어·중국어 업데이트 내역을 추가했다.

### 내일은 탁구왕

- 회귀 검증: **11건 통과**. 정상·구버전 보존, 손상·미래 버전 거절, 원본 보존, 새 플레이어 시작, 응답 유실과 새 진행도, 실제 충돌, 재확인 연결 실패, 캐시 공간 부족, 창 전환, 효과 줄이기를 다뤘다.
- 정적 배포 허용 목록에 공통 저장 검증기를 추가했다. 두 진입 HTML 모두 검증기를 인증 코드보다 먼저 읽는다.
- 날짜 2026-10-24의 네 언어 업데이트 내역을 추가했다.

테스트는 실제 함수·저장 클래스를 사용하고 브라우저 저장소·서버·화면 의존성만 모의 처리했다. 사용자 데이터나 운영 계정에 시험 기록을 쓰지 않았다. 브라우저 제어 도구가 시작되지 않아 직접 플레이·휴대전화·화면 촬영 검증은 수행하지 못했다. 공개 주소 확인과 논리 회귀 검증을 실제 기기 플레이 검증으로 표현하지 않는다.
