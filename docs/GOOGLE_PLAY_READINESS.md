# Google Play 출시를 전제로 한 공통 개발 기준

사용자 확정일·공식 정책 확인일: **2026-10-24**

모든 프로젝트는 향후 Google Play에서 Android 앱으로 출시할 계획으로 시작한다. 개발 전에 [프로젝트 기본 틀](../PROJECT_BASELINE.md), [스킬 적용 기준](GAMEDEV_SKILLS_GUIDE.md)과 함께 읽는다. 기존 프로젝트의 다음 기능 수정에도 관련 기준을 적용한다.

## 1. 개발 개요에 처음부터 기록할 것

| 항목 | 결정·확인할 내용 |
| --- | --- |
| 앱의 가치·출시 단위 | 모바일에서 끝낼 수 있는 핵심 작업·게임 흐름, 다른 앱과 구별되는 기능 |
| 기술·Android 경로 | 현재 엔진·프레임워크 버전, Android 내보내기·패키징, 필요한 SDK·플러그인 |
| 식별·업데이트 | 고유 applicationId/package name, 표시 버전과 증가하는 versionCode, 서명 키 보관 책임 |
| 조작·화면 | 터치·작은 화면·태블릿·글자 확대·뒤로가기·키보드·회전·안전 영역 |
| 상태·저장 | 홈 이동·잠금·프로세스 종료·재실행, 구버전 이관, 웹에서 Android로 기록 이전 |
| 데이터·권한 | 수집·전송·보관·삭제, 외부 SDK, 필요한 권한과 거절 시 동작 |
| 수익화·링크 | 무료·유료·광고·구독·디지털 상품 여부, 채널별 은행 이체 버튼 정책 |
| 검증·출시 | 초기 Android 시제품, 실기기, 내부·비공개 테스트, 스토어 자료 |

앱 식별자와 최소 지원 버전을 추측해 확정하지 않는다. 현재 엔진·프레임워크를 유지하고 실제 버전에 맞는 Android 지원을 확인한다.

## 2. 초기 시제품부터 Android 빌드

- 핵심 기능 하나가 완성되면 설치·실행 경로를 확인한다. 웹 실행 완료와 Android 출시 준비 완료를 구분한다.
- 게임 엔진은 해당 버전의 Android 내보내기와 플러그인 호환성을 확인한다. 웹 앱은 정적 파일·서버 의존성과 파일 선택·다운로드·클립보드·외부 링크를 Android에서 구현할 방법을 정한다.
- 플랫폼 의존 기능을 파일·공유·알림·외부 브라우저 등의 경계로 분리한다. 공통 게임 규칙·데이터 형식과 플랫폼 포장 코드를 불필요하게 결합하지 않는다.
- 웹 외피를 씌운 앱도 실제 모바일 기능·품질 기준을 충족해야 한다. 이름만 바꾼 반복 앱이나 단순 트래픽 유도용 앱을 출시 전략으로 삼지 않는다. [Google 스팸·반복 콘텐츠 기준](https://support.google.com/googleplay/android-developer/answer/9899034?hl=en)

## 3. 조작·뒤로가기·앱 수명 주기

- 키보드 없이 핵심 기능을 사용할 수 있게 한다. 충분한 터치 영역·글자 크기·포커스 표시·설명 있는 버튼을 제공한다.
- 노치·상태 표시줄·하단 제스처 영역·소프트 키보드가 조작을 가리지 않게 한다. 지원할 세로·가로 방향을 정하고 작은 화면과 태블릿에서 확인한다.
- 뒤로가기는 열린 메뉴·대화상자를 먼저 닫고 이전 화면으로 돌아간다. 진행을 잃을 수 있는 종료는 저장·확인 흐름을 마련한다.
- 홈 이동·외부 링크·전화·잠금·재실행 때 게임·음악·입력·저장이 일관되게 처리되게 한다. 메모리에만 있는 상태를 저장됐다고 안내하지 않는다. [Android 수명 주기](https://developer.android.com/guide/components/activities/activity-lifecycle)

## 4. 저장·업데이트·네트워크

- 저장 버전·이관·이전 정상본·손상 원문 보존을 설계한다. 업데이트 후 진행도·장비·설정·구매 권리를 확인한다.
- 웹 localStorage·IndexedDB가 Android 앱에 자동 이전된다고 가정하지 않는다. 필요한 경우 사용자가 선택하는 내보내기·가져오기나 계정 동기화를 제공한다.
- 오프라인·느린 연결·로그인 만료·중복 요청·서버 성공 후 응답 유실을 처리한다. 로컬 PC 전용 서버 기능은 모바일 접근 방식과 인증·지원 범위를 먼저 정한다.

## 5. 개인정보·권한·계정 삭제

- 분석·광고·오류 수집·로그인·지도 SDK까지 실제 데이터 흐름을 목록화하고 Data safety와 개인정보처리방침에 반영한다. 개인정보처리방침 URL과 앱 내부 진입점을 준비한다. [User Data 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)
- 위치·카메라·사진·알림 권한은 필요한 시점에 요청하고 거절 시의 동작을 구현한다. 파일 선택에 필요한 범위를 넘는 저장소 권한을 기본으로 요구하지 않는다.
- 가입 기능이 있으면 **앱 내부와 외부 웹에서 계정 삭제 요청**을 제공한다. 인증 계정·연결 데이터·보관 의무 항목을 함께 다룬다. 로그아웃·앱 삭제를 계정 삭제로 안내하지 않는다. [계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)
- 대상 연령·아동 대상 여부와 광고·동의 방식을 정한다. 비밀번호·서명 키·서버 비밀값은 앱 번들이나 공개 저장소에 넣지 않는다.

## 6. 결제·후원 버튼의 채널 구분

- 웹판의 후원 버튼은 `https://buymeacoffee.com/roky.studio`를 사용하고 유도 문구도 `로키스튜디오 후원`으로 표시한다. 기존 `#bank-transfer` 링크는 홈페이지 후원 안내에서 계속 지원한다. 후원을 게임 보상 지급 기능으로 연결하지 않는다.

- 웹 공통 메뉴의 전자책 링크 `https://litt.ly/roky.studio`도 Play 배포 때 검토한다. 외부 디지털 콘텐츠 구매 경로인지 확인하고, 앱별 정책 확인 전에는 웹 버튼을 Play 앱에 자동 포함하지 않는다. 웹 표식 `data-web-only-commerce`만으로 자동 제거되지는 않는다.
- Play 배포 앱의 디지털 상품·유료 기능·광고 제거·아이템·구독은 현행 Play 정책에 맞는 결제를 설계한다. 외부 웹페이지를 거치는 구매 유도도 검토한다. [Payments 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)
- Google FAQ에는 **전액이 창작자에게 가고 디지털 콘텐츠·서비스 이용 권리를 주지 않는 팁·지원금**을 P2P로 취급하는 조건이 있다. 배지·아이템·기능 해금을 대가로 주면서 이 예외에 해당한다고 가정하지 않는다. 국가·프로그램별 조건도 확인한다. [공식 결제 FAQ](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en)
- `web`·`google-play` 등의 배포 채널 설정을 둔다. Play의 외부 이체 버튼은 앱별 정책 확인 후 노출하고, 미확정이면 숨긴다. 도움말·홈페이지 링크에서 금지된 외부 결제로 이어지는 경로도 점검한다.
- 구매가 있으면 신뢰 가능한 검증, 복원, 취소·환불 시 권리 처리, 중복 지급 방지를 마련한다. 단순 계좌 복사 버튼을 구매 검증에 사용하지 않는다.

## 7. 빌드·서명·기술 요구

- 신규 Play 앱은 **AAB(Android App Bundle)** 배포를 준비한다. Play App Signing과 업로드 키의 보관·복구를 정하고 키·비밀번호를 커밋하지 않는다. [App Bundle 안내](https://developer.android.com/guide/app-bundle)
- **2026-10-24 확인:** 일반 Android 휴대폰 앱의 신규 제출·업데이트는 Android 16 **API 36 이상** 기준이다. 최소 지원 API와 target API를 구분하고 제출 직전에 다시 확인한다. [대상 API 요구](https://developer.android.com/google/play/requirements/target-sdk)
- 네이티브 라이브러리·게임 엔진·플러그인의 64비트와 **16KB 메모리 페이지** 호환성을 확인한다. 실제 AAB에서 생성한 배포 결과까지 검사한다. [16KB 페이지 지원](https://developer.android.com/guide/practices/page-sizes)
- 다운로드 크기·첫 실행 시간을 관리하고 필요하면 Play Asset Delivery 같은 경로를 검토한다. 개발 설정·디버그 화면·시제품 링크가 출시 번들에 섞이지 않게 한다.

## 8. 출시 전 확인

1. 실기기에서 설치·첫 실행·핵심 흐름·권한 거절·오프라인·뒤로가기·앱 전환·프로세스 종료 후 복구를 확인한다.
2. 업데이트 설치 후 이전 데이터와 권리를 확인한다. 낮은 성능 기기의 메모리·발열·프레임·충돌·응답 없음을 검토한다.
3. 이름·아이콘·스크린샷·설명·고객지원·개인정보 URL·대상 연령·콘텐츠 등급·광고·Data safety를 준비한다. 로그인이 필요하면 심사용 접근 방법을 마련한다.
4. 내부 테스트로 배포를 확인하고 계정에 해당하는 비공개 테스트·프로덕션 접근 요건을 확인한다. **2023-11-13 이후 만든 개인 개발자 계정은 현재 최소 12명이 연속 14일 참여하는 비공개 테스트 조건**이 있으며 충족 후 접근을 신청한다. 계정 유형을 확인하고 적용한다. [신규 개인 계정 테스트](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
5. 채널별 외부 결제·이체 링크, HTTPS, 외부 앱·브라우저 복귀, 도움말을 확인한다.
6. AAB·versionCode·서명·엔진·SDK·정책 확인일·기기·검증·배포 결과를 기록한다. 아직 하지 않은 Android 빌드나 Play 출시를 완료로 표시하지 않는다.
